## 1. Claude Code とは？

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   あなた ──→  [ ターミナル ]  ──→  Claude Code CLI      │
│                                        │                │
│                                        ▼                │
│                               ┌────────────────┐       │
│                               │  Claude AI     │       │
│                               │  (Sonnet/Opus) │       │
│                               └────────────────┘       │
│                                        │                │
│                              ┌─────────┴────────┐      │
│                              ▼                  ▼      │
│                        [ ファイル編集 ]   [ コマンド実行 ] │
│                              ▼                  ▼      │
│                        [ テスト実行 ]    [ Web 検索 ]   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

Claude Code は Anthropic 公式の **CLI ツール**です。
ターミナルから Claude AI と会話しながら、コードの作成・編集・テスト・デバッグを
AI がファイルを直接操作することで実現します。

**できること：**
- コードファイルの読み込み・編集・新規作成
- シェルコマンドの実行（git, npm, python など）
- Web 検索・URL コンテンツの取得
- CI/CD パイプラインへの組み込み（非対話型モード）
- MCP サーバー経由で外部サービスとの連携

## 3. 基本的な使い方

### 3-1. 対話型モード（Interactive Mode）

```
┌─────────────────────────────────────────────┐
│  Terminal                                   │
│                                             │
│  $ cd /path/to/myproject                    │
│  $ claude                                   │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │ 🤖 Claude Code                      │    │
│  │ > ここにプロンプトを入力してください  │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  終了: Ctrl+D または exit を入力             │
└─────────────────────────────────────────────┘
```

会話しながらコードを修正し、ファイル操作の許可/拒否をリアルタイムで行えます。

### 3-2. 非対話型モード（ワンショット）

```bash
# 一度だけ実行して終了
claude -p "このコードベースの構造を説明して"

# パイプでログを分析
cat error.log | claude -p "エラーの原因を特定して"

# ビルドエラーを自動修正
npm run build 2>&1 | claude -p "このビルドエラーを修正して"

# 前回の会話を続行
claude -c -p "次のステップを教えて"
```

### 3-3. セッション管理

```
┌─── セッション再開オプション ──────────────────────┐
│                                                   │
│  claude -c           # 最新セッションを再開        │
│  claude -r "名前"    # セッション名で再開          │
│  claude --resume     # 対話的に選択して再開        │
│                                                   │
└───────────────────────────────────────────────────┘
```

### 3-4. ファイル参照の方法

```
ユーザー入力中に...

  > @src/       ← @ を入力するとパス補完が起動
    ┌─────────────────────┐
    │ src/components/     │
    │ src/utils/          │
    │ src/api/index.ts ←選択
    └─────────────────────┘

  > @src/api/index.ts の認証部分を確認して
```

`@` でファイルパスを補完しながら特定ファイルを参照できます。

## 6. パーミッションモード

Claude がツールを実行する際の承認レベルを設定します。

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  安全 ◄────────────────────────────────────────► 自動化        │
│                                                                 │
│  [default]  [plan]  [acceptEdits]  [auto]  [bypassPermissions] │
│      │         │         │           │            │             │
│    都度     実行前     ファイル     AI が        全て          │
│    確認    計画確認   編集のみ    判定する      自動承認       │
│             ↓         自動承認                                  │
│           複雑な                                                │
│           変更に最適                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### モード切り替え方法

```bash
# 起動時に指定
claude --permission-mode plan

# Shift+Tab で対話中に循環切り替え
```

### ツールごとの細かい設定

```json
// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(git *)",      // git コマンドは全て許可
      "Bash(npm test)",   // npm test のみ許可
      "Read",             // ファイル読み込みは全て許可
      "Edit"              // ファイル編集は全て許可
    ],
    "deny": [
      "Bash(rm -rf *)",   // 危険な削除コマンドは拒否
      "Bash(sudo *)"      // sudo は拒否
    ]
  }
}
```

## 8. MCP サーバー連携

MCP（Model Context Protocol）を使って Claude を外部サービスに接続できます。

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   Claude Code                                                │
│       │                                                      │
│       ├── MCP Server: GitHub ──→ Issues, PRs, Repos         │
│       ├── MCP Server: Slack  ──→ チャンネル, メッセージ     │
│       ├── MCP Server: DB     ──→ PostgreSQL, MySQL          │
│       └── MCP Server: カスタム ──→ 自社システム連携         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 設定方法

**ファイル:** `.claude/.mcp.json`（プロジェクト）または `~/.claude/.mcp.json`（ユーザー）

```json
{
  "mcpServers": {
    "github": {
      "command": "node",
      "args": ["~/mcp-github/index.js"],
      "type": "stdio",
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "remote-api": {
      "url": "https://api.example.com/mcp",
      "type": "http"
    }
  }
}
```

### 対話型で設定

```
> /mcp
  ┌── MCP サーバー管理 ──────────────────────────┐
  │  [追加] [削除] [接続テスト] [ログ確認]        │
  └──────────────────────────────────────────────┘
```

## 9. Hooks（自動化）

特定のイベントをトリガーにシェルコマンドや HTTP リクエストを自動実行できます。

```
┌──────────────── Hook イベントフロー ─────────────────────┐
│                                                          │
│  SessionStart ──→ セッション開始時に実行                  │
│                                                          │
│  UserPromptSubmit ──→ プロンプト送信前に実行              │
│                                                          │
│  PreToolUse ──→ ツール実行前                             │
│      │                                                   │
│      ▼                                                   │
│  [Bash / Edit / Read / WebSearch ...]                    │
│      │                                                   │
│      ▼                                                   │
│  PostToolUse ──→ ツール実行後                            │
│                                                          │
│  Stop ──→ セッション終了時に実行                          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 設定例

```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": { "tool": "Edit" },
        "hooks": [
          {
            "type": "command",
            "command": "prettier --write {path}"
          }
        ]
      }
    ],
    "SessionStart": [
      {
        "type": "command",
        "command": "echo '🚀 Claude Code セッション開始' && date"
      }
    ]
  }
}
```

**実用例：**
- ファイル編集後に自動フォーマット（Prettier, Black, gofmt）
- ファイル保存時にリントチェック実行
- セッション開始時に git pull して最新コードを取得
- セッション終了後にレポートを Slack へ通知

## 11. Agent SDK

Claude Code の機能をプログラムから操作する SDK です。

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  あなたのアプリ                                           │
│      │                                                   │
│      │  import { query } from "@anthropic-ai/sdk"        │
│      │                                                   │
│      ▼                                                   │
│  Claude Code SDK                                         │
│      │                                                   │
│      ▼                                                   │
│  Claude AI ──→ ファイル操作 / コマンド実行 / Web検索      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### TypeScript / JavaScript

```typescript
import { query } from "@anthropic-ai/sdk";

const result = await query({
  cwd: process.cwd(),
  prompt: "このプロジェクトのアーキテクチャを説明して"
});

console.log(result.messages);
```

### Python

```python
from anthropic_sdk.claude_code import query

result = query(
    cwd="/path/to/project",
    prompt="全てのリントエラーを修正して"
)

print(result['messages'])
```

### セッション継続

```typescript
// 最初のステップ
const result1 = await query({
  prompt: "ステップ1: コードを分析して",
  continue: true
});

// セッションを引き継いで続行
const result2 = await query({
  sessionId: result1.sessionId,
  prompt: "ステップ2: 修正を実装して"
});
```

## 12. ベストプラクティス

### 明確な指示を書く

```
❌ 悪い例
──────────
> バグを直して

✅ 良い例
──────────
> src/auth/login.ts の JWT 検証で、
> 有効期限切れのトークンが通過してしまう問題を修正して。
> 修正後に npm test を実行して全テストが通ることを確認して。
```

### 段階的なタスク分割

```
┌─── 大きなタスクを分割する ──────────────────────────────┐
│                                                         │
│  ❌ 「ユーザー認証を全部実装して」                       │
│                                                         │
│  ✅ 手順を明示する:                                     │
│   1. src/db/schema.ts を確認して user テーブルを把握    │
│   2. パスワードハッシュ化のユーティリティを作成          │
│   3. ログイン API エンドポイントを実装                   │
│   4. テストを書いて実行                                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### コンテキスト管理

```
長い会話が続いたら...

/compact    ← 会話を要約して重要な部分だけ残す
            （API コスト削減・応答速度向上）

/clear      ← 会話を完全にリセット
            （新しいタスクを始めるとき）
```

### CI/CD への組み込み

```yaml
# GitHub Actions での使用例
- name: AI コードレビュー
  run: |
    claude --permission-mode auto \
      -p "差分をレビューして問題を報告して" \
      --dangerously-skip-permissions
```

### よく使うパターン

```bash
# エラーログを分析して修正
npm run build 2>&1 | claude -p "このエラーを修正して"

# テスト失敗を調査
npm test 2>&1 | claude -p "なぜテストが失敗しているか分析して"

# コードレビュー
git diff main | claude -p "このPRをレビューして問題点を指摘して"

# ドキュメント生成
claude -p "src/ 以下のコードから README.md を生成して"
```

## 主要な環境変数

| 変数 | 用途 |
|------|------|
| `ANTHROPIC_API_KEY` | API キー（Console 利用時） |
| `CLAUDE_CODE_DEBUG_LOGS_DIR` | デバッグログの保存先 |
| `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` | バックグラウンドタスク無効化 |

## トラブルシューティング

```
問題: ログインできない
──────────────────────────────────────
$ claude auth logout
$ claude auth login

問題: パーミッション確認が多すぎる
──────────────────────────────────────
.claude/settings.json に allow ルールを追加する

問題: 会話が長くなってレスポンスが遅い
──────────────────────────────────────
/compact でコンテキストを圧縮する

問題: MCP サーバーが接続できない
──────────────────────────────────────
/mcp でサーバー状態を確認し、
認証情報・URL・コマンドパスを再確認する

問題: モデルが応答しない
──────────────────────────────────────
$ claude --debug
でデバッグログを確認する
```
